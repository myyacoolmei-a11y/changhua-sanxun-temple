彰化三巡府跨裝置雲端同步修正套件（測試版）

重要：此版本不是已在正式環境驗收的成品。不要直接替換正式系統。
先在最常使用的電腦上保留所有瀏覽器資料；最好先按每個模組的 CSV 匯出。
建議先複製一套 Railway 測試服務與獨立 PostgreSQL 測試資料庫，驗證成功後再安排正式上線。

套件內容：
- index-synced.html：已加入雲端同步的完整前端；維持原畫面
- temple-sync.js：PostgreSQL 儲存／讀取 API，登入驗證、權限篩選、版本衝突保護
- apply_sync.py：在原始專案內套用修改，並備份原 server.js 與 index.html

套用：
1. 在 Mac 下載 GitHub 儲存庫原始碼 ZIP 並解壓縮。
2. 將本套件的 index-synced.html、temple-sync.js、apply_sync.py 放進儲存庫「最外層」（server.js 的旁邊）。
3. Mac 終端機切換至該資料夾後執行：python3 apply_sync.py
4. 完成後查看差異（git diff），執行 node --check server.js、node --check temple-sync.js。
5. 先部署至測試環境；確認登入、資料匯入、讀取、修改、跨裝置、權限、公開報名流程沒有回歸問題。
6. 新資料庫首次開啟時尚未有雲端業務資料；用「最新資料的電腦」登入最高管理員，點右下角「下載此裝置資料備份」，確認內容後點「管理員首次匯入」。
7. 其他裝置重新開啟，即可取得雲端資料。若顯示儲存衝突，先下載本機備份，不要強行覆蓋。

注意限制：
- 採用一份修訂版本號的共用快照；同時間兩台裝置更改會拒絕較舊版本，避免靜默覆寫。不是逐筆合併。
- 此版本的同步為視窗重新取得焦點或每 30 秒重新讀取，不是 WebSocket 即時推播。
- 只有最高管理員能初始化；初始化只允許一次。
- 依據後端授權模組控制修改與回傳；仍應在測試環境進行權限及資安驗證。
- 原本的公開報名 API 不在這次後端模組中；需確認原公開報名功能本身可用。
- 不要將真實信眾個資上傳到公開 GitHub；程式碼不應包含資料庫密碼。
